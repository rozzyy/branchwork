# M4 Plan — GitHub

M4 adds GitHub integration following spec §6.7 and the arch diagram
(`github::{auth (device flow), rest/graphql (octocrab), poller, cache}`),
depending on M1 (repos) plus M2 (PR diff) and M3 ("Terminal in worktree").
Work proceeds one task at a time on stage branches, with a manual checkpoint
after each stage. The token lives in the macOS Keychain only — never in
SQLite or logs (spec §6.7, §6.10).

## Cross-stage constraints

- Token in Keychain only; never SQLite, logs, or the WebView. PAT entry uses a password field and is cleared from memory after storing.
- All GitHub traffic goes through typed Tauri commands; no generic shell access, no token in URLs.
- Reuse the shared diff renderer for PR files; reuse worktree/terminal flows for Start → worktree and Terminal in worktree.
- Each stage runs `./init.sh`, targeted and full Playwright tests as applicable, code review, and focused security review for auth/secret/network surfaces. Record manual checks and stop at the stage checkpoint.
- Do not bump the version until M4 is complete. Do not commit or push until the user approves a checkpoint; create one stage commit and fast-forward into `main` only after explicit commit authorization.
