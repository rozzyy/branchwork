# M5 Plan — Launchpad and Inbox UI parity

M5 begins after the M4 `v0.4.0` release. This stage aligns the existing
Launchpad and Inbox UI with their visual reference in
`docs/design/prototype.html`; it keeps M4's real data paths and interactions.

## Stage 1 — Launchpad and Inbox redesign

| Task | Scope | Depends on |
|---|---|---|
| M5-01 Launchpad + Inbox prototype parity | Three-column Launchpad dashboard and KPI hero; two-pane Inbox with category filters and selected-item detail. Preserve existing data bounds, safe routes, and action behavior per `docs/superpowers/specs/2026-11-12-m5-launchpad-inbox-ui-parity.md`. | M4 Stage 4 |

Manual checkpoint: verify both screens at the prototype desktop size and at a
narrow stage width; verify Launchpad scope/actions and Inbox filtering,
selection, read/done/snooze flows. Stop for user approval before the stage
commit and merge.

## Stage constraints

- Use the prototype's layout, spacing, surfaces, and hierarchy as the visual
  source of truth. Keep visible UI copy in English per `CLAUDE.md`.
- No new backend or GitHub calls for this visual task. Keep existing request
  and collection limits.
- Follow the task's performance/security constraints and the repository's
  one-feature-at-a-time workflow.
